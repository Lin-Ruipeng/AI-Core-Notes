# MCP 学习笔记

## 理解MCP

其实最简单的就是把MCP理解为一个命令行工具，比如 `ruff` 本质上就是一个CLI

但是现在，你希望更够更加自动化一点，而且不要污染环境，所以，以前你会运行

```bash
uv tool install ruff # 持久化安装，这会把这个工具永久注册到环境变量里
ruff check . # 你在系统里可以调用这个工具
```

现在相当于临时安装，用完就卸载，那么你可以这样：

```bash
uvx ruff check .
```

这行命令会把 `ruff` 工具下载到一个临时环境里，也就是创建了一个缓存。（尤其是这里的 `uvx` 完全等价于 `uv tool run`）

但是实际上，完整的MCP还需要把这个MCP提供了什么工具，每个工具各自有什么作用，这些信息提前塞入上下文中，所以需要一个专门的装饰器来完成这些任务。（因为MCP协议在运行的时候是存在初始化流程，把这些东西返回出来塞入模型上下文的）

## 代码架构

直接用 `mcp` 这个库，然后先创建一个实例，接着需要使用装饰器注册一些工具，同时写好每个工具的作用和参数说明，最后还需要运行这个实例，运行的时候才是一个真正可以调用的**MCP服务器**

## 配置说明

本项目所展示的代码在Cline插件上成功运行（只需要注意文件绝对路径的问题），但是会注意到，配置文件用的居然是 `uv` 命令，这是因为本质上MCP服务器就是让一个mcp库的实例对象运行起来就行，由于Cline插件没法接受 `--from` 这种参数，所以没办法写成更为常见的 `uvx` 的格式。

所以本仓库的这个配置 json 的写法并不够优雅 / 规范。

更加规范的写法应当是：

```json
{
    "mcpServers": {
        "time": {
            "command": "uvx",
            "args": [
                "--from",
                "./time_mcp.py", # 这里改成正确的文件路径
                "time_mcp.py"
            ],
            "env": {
                "TZ": "Asia/Shanghai" # 本项目没用到
            }
        }
    }
}
```
